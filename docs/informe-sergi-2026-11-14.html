1. Resumen ejecutivo

Mytarik ya no es un prototipo vacío. El proyecto tiene una base técnica funcional para clasificar mercancías con códigos CN8/TARIC10, una API y una interfaz web, una base vectorial, un clasificador EU separado del flujo HS6 y una batería de pruebas. También se ha validado el flujo con documentos sintéticos y se ha construido la infraestructura para ingerir decisiones EBTI.

La conclusión principal es clara:

La arquitectura y el flujo EU funcionan; lo que falta es el dato operativo completo.
El catálogo eu_taric contiene solo 6 códigos de muestra. Sin el catálogo TARIC/CN completo y actualizado, la app no puede operar como producto real.

3. Qué funciona hoy

Clasificación EU

  • El clasificador EU devuelve CN8 y TARIC10; no devuelve HS6.
  • CLASSIFICATION_MODE=eu es el modo por defecto.
  • legacy_hs6 solo se activa de forma explícita; no hay fallback automático.
  • Las respuestas EU se serializan en la API web y se muestran en la UI.

Consulta HS6 separada

  • /hs6/lookup usa el retriever HS6 y no llama al clasificador EU.
  • La UI tiene una sección independiente con el aviso: “Referencia internacional. No usar para la declaración aduanera UE.”
  • HS6 no contamina la tabla EU ni el payload del clasificador.

Datos y evaluación

  • hs_codes: 5.613 códigos HS6 de referencia.
  • ebti_decisions: 90.048 decisiones EBTI cargadas.
  • Traducción local ES/EN con OPUS-MT + CTranslate2, sin Azure.
  • Evaluación sintética: 3 documentos, 10 líneas, 10/10 CN8.
  • Parser PDF corregido: la factura comercial pasó de 19 líneas extraídas a 4.

5. Decisiones de diseño

  • EU-first: la operativa diaria usa CN8/TARIC10. HS6 solo se consulta de forma explícita y separada.
  • Sin fallback silencioso: si el modo EU falla, no se cae a HS6.
  • Sin Azure: clasificación y traducción funcionan en local; no se necesitan credenciales de Azure.
  • EBTI no es TARIC: las decisiones EBTI son jurisprudencia de apoyo, no el catálogo operativo.
  • Revisión humana: la IA propone; el agente aduanero valida. No es asesoramiento jurídico.

7. Riesgos y limitaciones

1. Catálogo EU incompleto — riesgo crítico.
Solo hay 6 códigos de muestra. Sin el TARIC/CN completo no se puede validar la clasificación real ni las medidas.
2. Medidas aduaneras y CustomsPanel.
El panel de medidas sigue trabajando con lógica HS6. Hay que adaptarlo a TARIC10, origen, régimen y medidas.
3. EBTI incompleto.
Hay 90.048 decisiones cargadas de 123.429 válidas. La ingestión se pausó; hay snapshot y se puede reanudar.
4. Agentes locales lentos.
Hermes y OpenCode con Laguna funcionan, pero exploran y compactan demasiado. Laguna rinde ~13,8 tok/s (3 GPUs, 260 W). Son útiles para tareas pequeñas y revisión, no como ingenieros autónomos.
5. Sin commit y sin auditoría de producción.
El trabajo está en el árbol local, sin commit. Faltan historial de aprobaciones, trazabilidad y aviso legal para cliente.
